# Shared Team Asset Check

Before sharing a prompt, skill, checklist or template as a team method, check every line below.

| Check | Yes or no |
| --- | --- |
| At least two people have found the method useful in a real or fictional test |  |
| The job is specific enough to recognise |  |
| The safe inputs are clear |  |
| The output format is easy to check |  |
| The common ways it goes wrong are written down |  |
| A person owns the final decision and action |  |
| No customer message or system change happens automatically |  |
| An owner will review it again |  |
| For recurring work, the trigger, running account and maintained connections are agreed |  |
| The intended audience and who reviews or approves each result are clear |  |
| A missed run, stale source or failed output has a named exception route |  |
| The method can continue or be retired safely if its original creator leaves |  |

The recurring-work rows apply only where the method actually repeats or runs for a team. For a simple shared prompt or template, mark them **not applicable** with a reason; do not invent an execution account.

If any applicable answer is no, keep the method in the learning log. It may be useful, but it is not ready to become a shared team asset. A shared page or output is not by itself proof of a team-owned recurring process. Before judging a repeated method successful, compare accepted results across several runs, including review time, failures and upkeep.
