# Manager Playbook

This is for the manager who has people asking, “What should I actually use AI for?” and does not want to answer with either a blanket ban or a motivational speech.

The aim is to help a team learn one useful way of working at a time, without turning the exercise into performance monitoring, a large change programme or an unapproved technology project.

## The Manager's Job

You are not there to become the team expert on every AI tool. Your job is to make four things easier:

1. choosing a safe task worth trying;
2. making it clear what good looks like;
3. helping people improve an early attempt; and
4. deciding whether a useful method should become a shared asset.

## Start With One Team Problem

Ask the team:

> Which repetitive part of our work would be useful to make clearer, quicker or more consistent, without changing a customer decision or a system automatically?

Good early candidates:

- first drafts of follow up emails;
- preparing questions for a meeting;
- turning approved notes into actions;
- organising a handover summary; or
- reviewing a fictional example together.

Avoid early tests involving large data exports, customer messaging without review, pricing, contracts, personal data or CRM automation.

## Run the First Session

Use [First Team Session](../workshops/first-team-session.md). The useful outcome is not a polished prompt. It is one shared example of:

- the task;
- the safe input;
- the output shape;
- the check a person applies; and
- what the team learned.

Use the [Team Learning Log](../templates/team-learning-log.md) as you go.

## Support the First Few Tests

Ask volunteers to use one small method during normal work only when the information and tool are approved. The manager should help remove friction, not inspect every attempt.

At the end of a test, ask:

1. What part of the output was genuinely useful?
2. What did you have to correct?
3. What input made the difference?
4. Would another person understand how to use this?
5. Is it safe and useful enough to test again?

If the answer is “not really”, that is a useful result. Capture it and move on.

## Help Someone Improve a Weak First Prompt

Use [Improve a First Prompt](improve-a-first-prompt.md). The usual fix is not more clever wording. It is a clearer job, better input, a useful output shape and an explicit human check.

## Decide What Becomes Shared

Do not turn every good private prompt into team policy. Use the [Shared Team Asset Check](../checks/shared-team-asset-check.md).

An asset is ready only when:

- more than one person has found it useful;
- the safe input is clear;
- the output is easy to check;
- common mistakes are known;
- someone owns keeping it current; and
- it does not make decisions or actions automatically.

If it is not ready, keep it in the learning log rather than publishing it as a team standard.

## Review Every Month

Run a short review:

| Ask | Why it matters |
| --- | --- |
| What did people use more than once? | Repetition is stronger evidence than enthusiasm |
| What saved effort or improved quality? | It stops the review becoming a list of favourite tools |
| What created mistakes or uncertainty? | Failure is part of safe adoption |
| What should stay individual? | Not every method needs standardising |
| What is ready for a shared asset? | The team only scales what has earned it |

The manager decides what the team does next. AI does not make that call.
